В 2026 году для Arch Linux берём GPT. UEFI-прошивки работают с ним из коробки, GPT защищает от повреждений загрузочной записи и поддерживает диски больше 2 ТБ. MBR нужен только на старых машинах с Legacy BIOS. Разберём, какие разделы создать, сколько отдать каждому места и как это сделать через fdisk.

## GPT или MBR: что выбрать в 2026 году

Если компьютер поддерживает UEFI — берите GPT:

- **Резервная копия таблицы** в конце диска. Сломалась основная запись — система поднимет резервную. В MBR такой страховки нет.
- **Нет лимита в 4 раздела.** GPT создаёт до 128 разделов без «расширенных» и «логических».
- **Диски больше 2 ТБ** работают только с GPT.
- **Каждый раздел имеет уникальный GUID**, надёжнее привязки по номеру.

MBR остаётся актуален на древних ноутбуках с чистым BIOS. Если есть UEFI (а с 2012 года это 99% железа) — однозначно GPT.

## Какие разделы нужны для Arch Linux

Минимальная схема UEFI + GPT:

| Раздел | Точка монтирования | ФС | Размер |
|--------|-------------------|-----|--------|
| ESP | `/boot` или `/efi` | FAT32 | 512 МБ–1 ГБ |
| Корень | `/` | ext4 или btrfs | 50–100 ГБ |
| Swap | — | swap | по необходимости |

**ESP** — обязательный раздел для UEFI-загрузки. Сюда складываются ядро, initramfs и загрузчик (GRUB или systemd-boot). АрхВики рекомендует 1 ГБ — хватит на несколько ядер и обновлений. На дуалбуте с Windows можно смонтировать общий ESP.

**Корень** — минимум 23–32 ГБ для базовой установки, на практике 50–100 ГБ хватит и на несколько DE, и на пакеты из AUR.

**/home** — если планируете btrfs-снапшоты, держите `/home` на корне и бэкапьте через снапшоты. Если хочется переустанавливать систему, не трогая данные — `/home` отдельно.

### Схема для BIOS + MBR

На старом железе без UEFI:

| Раздел | Точка монтирования | Тип |
|--------|-------------------|-----|
| `/boot` | ext2/ext4 | загрузочный (флаг boot) |
| `/` | ext4 | корень |
| swap | swap | подкачка |

Здесь `/boot` обязателен — GRUB должен иметь доступ к ядру на простой файловой системе.

### Btrfs-подтома

Если выбрали btrfs, разделы заменяются подтомами: `@` (корень), `@home` (/home), `@snapshots` (снапшоты). Один раздел, внутри несколько логических разделов. Гибко и удобно для отката.

## Сколько места под корень, /home и swap

- **Корень.** Базовая установка Arch с одним DE — 10–15 ГБ. С браузером, LibreOffice и играми — 30–50 ГБ. Если `/home` на том же разделе — 100 ГБ с запасом.
- **/home.** Пустите сюда остаток диска под данные.
- **Swap.** Старое правило «в два раза больше RAM» давно неактуально:

| Сценарий | Рекомендация |
|----------|-------------|
| 16+ ГБ RAM, десктоп | swapfile 4–8 ГБ или zram |
| Гибернация | swap = размер RAM |
| Мало RAM (4 ГБ и менее) | swap-раздел 4–8 ГБ |
| Сервер | 1–2 ГБ |

**zram** — сжатый swap прямо в оперативке. Не занимает место на диске, быстрее классического swap. Для десктопа отличный вариант:

```bash
sudo pacman -S zram-generator
```

Создаёт `/dev/zram0` с алгоритмом zstd автоматически. Если нужен swap-файл — `fallocate -l 4G /swapfile && mkswap /swapfile && chmod 600 /swapfile`.

## Как разметить диск через fdisk пошагово

Допустим, у нас NVMe-диск `/dev/nvme0n1` (или SATA `/dev/sda`). Смотрим текущее состояние:

```bash
sudo fdisk -l /dev/nvme0n1
```

Запускаем интерактивный режим и создаём разметку:

```bash
sudo fdisk /dev/nvme0n1
```

В fdisk вводим последовательно:

```
g       → новая GPT-таблица
n  1  [Enter]  +1G    → раздел ESP, 1 ГБ
t  1             → тип EFI System
n  2  [Enter]  +50G   → корень, 50 ГБ
n  3  [Enter]  +8G    → swap, 8 ГБ
t  19            → тип Linux swap
n  4  [Enter]  [Enter] → /home, весь остаток
w       → записать
```

Форматируем всё:

```bash
sudo mkfs.fat -F 32 /dev/nvme0n1p1
sudo mkfs.ext4 /dev/nvme0n1p2
sudo mkswap /dev/nvme0n1p3
sudo swapon /dev/nvme0n1p3
sudo mkfs.ext4 /dev/nvme0n1p4
```

Монтируем и ставим систему:

```bash
sudo mount /dev/nvme0n1p2 /mnt
sudo mount --mkdir /dev/nvme0n1p1 /mnt/boot
sudo mount /dev/nvme0n1p4 /mnt/home
```

После этого запускаем `pacstrap` и продолжаем установку как описано в [пошаговом руководстве](https://ordanax.github.io/ustanovka-archlinux-2019-za-15-minut).

## Частые вопросы

**Нужен ли отдельный /boot на UEFI?**

На UEFI `/boot` — это ESP (раздел FAT32). Вы его уже создали. Смонтируйте в `/boot` или `/efi`. Отдельный Linux-раздел для `/boot` нужен только на Legacy BIOS.

**Можно ли обойтись без swap?**

Да, на десктопе с 16+ ГБ RAM можно жить без swap. Но гибернация работать не будет. Минимальный swap (4 ГБ) или zram — дешёвая страховка. Подробнее — на [странице Swap в ArchWiki](https://wiki.archlinux.org/title/Swap).

**Если корневой раздел заполнился?**

Разделы расширить нельзя (кроме btrfs и LVM). Если `/home` отдельно — перенесите данные. Если всё на корне — почистите pacman cache: `sudo pacman -Scc`. Про это подробнее — в статье [«Корневой раздел заполняется»](https://ordanax.github.io/kornevoy-razdel-zapolnyaetsya), а об обновлении пакетов — в [«pacman: частичное обновление»](https://ordanax.github.io/pacman-chastichnoe-obnovlenie).

**ext4 или btrfs?**

ext4 — проверен, быстр, прост. Btrfs даёт снапшоты (откат за секунды), сжатие, контроль целостности. Для большинства ext4 оптимален. Btrfs — если планируете снапшоты через Timeshift или snapper.

## Заключение

Разметка диска под Arch сводится к последовательности: GPT-таблица, ESP (1 ГБ), корень (50–100 ГБ), при необходимости swap и `/home`. Команды fdisk одинаковы для SATA и NVMe. Не забудьте смонтировать ESP перед `pacstrap` — без этого система не загрузится. Если сомневаетесь — начните с одного корня и swapfile, расширите по мере необходимости. Установка по [чек-листу](https://ordanax.github.io/chek-list-po-ustanovke-archlinux-2019) поможет не пропустить ни одного шага.
