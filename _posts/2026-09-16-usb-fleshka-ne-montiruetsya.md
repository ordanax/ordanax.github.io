Флешку вставляете, а она молчит: ни в файловом менеджере, ни в Nautilus, ни где-то ещё. В большинстве случаев причина одна: в сессии нет udisks2 с gvfs, или демон не запущен. Arch поставляется без графической оболочки, автоматическое монтирование появляется только когда оно явно установлено. Разберём основные сценарии и дойдём до ручного монтирования на всякий случай.

## Почему флешка не монтируется автоматически

В десктопных средах за автоматическое монтирование отвечает связка udisks2 + gvfs. Вставляете USB-накопитель, udev определяет устройство, udisks2 подхватывает и монтирует в `/run/media/$USER/ИМЯ_ФЛЕШКИ`. Нет одного звена — ничего не происходит.

В Arch после чистой установки сервисы не активируются сами:

1. Установлен тайлинговый WM (i3, sway, bspwm), но не было задачи ставить DE.
2. Пакет udisks2 есть, но сервис `udisks2.service` не запущен.
3. Нет gvfs для интеграции в файловый менеджер.

В [GNOME](https://ordanax.github.io/gnome-ustanovka-linux) и [XFCE](https://ordanax.github.io/xfce) всё это уже на месте. Тайлинговый WM без DE — монтирование через udisks2 в консоли.

## Как проверить и запустить udisks2

Первым делом убедимся, что пакет установлен, и запустим сервис:

```bash
pacman -Qs udisks2                     # установлен?
sudo pacman -S udisks2                 # если нет
sudo systemctl enable --now udisks2.service   # запуск
```

Вставьте флешку заново. В консоли (без DE) управляйте монтированием через `udisksctl`:

```bash
udisksctl info -b /dev/sdb1     # информация о разделе
udisksctl mount -b /dev/sdb1    # примонтировать
udisksctl unmount -b /dev/sdb1  # отмонтировать
```

## Как в fstab примонтировать флешку навсегда

Если флешка нужна всегда, пропишите её в `/etc/fstab`. Способ надёжный, не зависит от udisks2. Сначала найдите UUID:

```bash
lsblk -f
```

Вывод покажет имя устройства, UUID, файловую систему и метку. Добавьте в `/etc/fstab` строку:

```
UUID=A1B2-C3D4   /mnt/usb   vfat   defaults,relatime,nofail   0 0
```

Важные опции:

- **defaults** — стандартный набор (rw, suid, dev, exec, auto, nouser, async).
- **relatime** — обновление времени доступа с оптимизацией, не при каждом чтении.
- **nofail** — система загрузится, даже если флешка не воткнута. Без него boot зависнет на 90 секунд.

Тип файловой системы подставьте свой: `vfat` для FAT32, `exfat` для exFAT, `ext4` для Linux-формата. Точку монтирования создайте заранее:

```bash
sudo mkdir -p /mnt/usb
```

## Как примонтировать флешку вручную

В любой ситуации сработает классика:

```bash
lsblk -f
sudo mkdir -p /mnt/usb
sudo mount /dev/sdb1 /mnt/usb
```

Размонтирование:

```bash
sudo umount /mnt/usb
```

Если выдаёт «unknown filesystem type», поставьте пакет поддержки. Для exFAT — `exfatprogs`, для NTFS — `ntfs-3g`:

```bash
sudo pacman -S exfatprogs
```

## Если не работает даже ручное монтирование

Вот чеклист по частым проблемам:

**Файловая система повреждена.** Проверьте и исправьте:

```bash
sudo fsck.vfat /dev/sdb1      # для FAT32
sudo fsck.exfat /dev/sdb1     # для exFAT
sudo fsck.ext4 /dev/sdb1      # для ext4
```

**Устройство busy.** Процесс держит файловую систему. Найдите виновника:

```bash
lsof /mnt/usb
fuser -vm /mnt/usb
```

Закройте процесс или используйте `umount -l` (ленивое размонтирование).

**Права доступа.** Проверьте владельца точки монтирования:

```bash
ls -la /mnt
ls -la /run/media/$USER/
```

Если точка принадлежит root, а вы обычный пользователь, монтируйте с явными uid/gid:

```bash
sudo mount -o uid=1000,gid=1000 /dev/sdb1 /mnt/usb
```

**Правила udev.** Кастомные [правила udev](https://ordanax.github.io/udev-pravila-ustroystv) могут конфликтовать со стандартным монтированием. Проверьте `/etc/udev/rules.d/` и `~/.config/udev/rules.d/`.

**Диск с шифрованием LUKS.** Сначала раскройте его:

```bash
sudo cryptsetup open /dev/sdb1 myusb
sudo mount /dev/mapper/myusb /mnt/usb
```

## systemd-mount: современный способ

В systemd есть утилита `systemd-mount`, которая сочетает удобство udisks2 и надёжность fstab:

```bash
systemd-mount /dev/sdb1 /mnt/usb
systemd-umount /mnt/usb
```

Полезно для временных накопителей, которые не хочется прописывать в fstab. Тип файловой системы определяется автоматически.

## Частые вопросы

**Почему в GNOME флешка монтируется сама, а в i3 — нет?**

GNOME включает udisks2 + gvfs из коробки. В тайлинговых WM этих компонентов обычно нет. Установите `udisks2`, запустите сервис `udisks2.service` и используйте `udisksctl` для управления монтированием из консоли.

**Безопасно ли выдергивать флешку без unmount?**

Нет. Даже если кажется, что ничего не пишется, кэш ядра может держать данные в буфере. Всегда выполняйте `udisksctl unmount` или `umount`. Если флешка не размонтируется («busy»), проверьте `lsof` и закройте держащие её процессы.

**Файловый менеджер видит флешку, но не может открыть. Пишет «no permission».**

Скорее всего, у смонтированной точки нет прав на чтение для вашей группы. Проверьте `ls -la /run/media/$USER/` и попробуйте смонтировать с явными uid/gid через ручной `mount -o`.

**Как узнать, какая файловая система на флешке?**

```bash
lsblk -f | grep sdb
```

Поле `FSTYPE` покажет формат: `vfat`, `exfat`, `ext4`, `ntfs` и так далее.

**Можно ли сделать автоматическое монтирование для конкретного USB без fstab?**

Да, через правила udev или через автозапуск `udisks2.service` в конфигурации вашего оконного менеджера. Подробнее о [настройке Ventoy и мультизагрузочных флешек](https://ordanax.github.io/ventoy) читайте в отдельной статье.

## Заключение

В большинстве случаев проблема с автоматическим монтированием USB сводится к одному: в Arch нет udisks2 или он не запущен. Установите пакет, активируйте сервис, и файловый менеджер начнёт видеть флешки. Для особых сценариев (постоянное подключение, шифрованные диски) используйте fstab с правильными опциями. Ручное монтирование через `mount` — универсальный запасной вариант, который работает всегда.
